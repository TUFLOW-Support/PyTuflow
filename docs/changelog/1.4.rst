ARR Data Hub v1.1 Update
------------------------

The ``pytuflow-arr`` :ref:`CLI tool <pytuflow-arr>` has been updated for the `2026 v1.1 ARR Data Hub Update
<https://data-dev.arr-software.org/changelog>`_.

The update includes:

- Support for frequent events: ``12EY``, ``6EY``, ``4EY``, ``3EY``, and ``2EY``
- Support for 1990 baseline rainfall losses

Progress Callback
-----------------

.. note::

    This feature is considered experimental.

Mesh result types have a new, experimental, optional argument in some of their data extraction methods that reports
the progress. A callback routine, taking two integer arguments, can be passed in so that the calling program or routine
can implement a progress bar if desired.

The supported routines are:

- :meth:`~pytuflow.XMDF.time_series`
- :meth:`~pytuflow.XMDF.section`
- :meth:`~pytuflow.XMDF.profile`
- :meth:`~pytuflow.XMDF.curtain`
- :meth:`~pytuflow.XMDF.flux`

.. note::

    The progress reported is not very granular. This is to keep the methods as optimised as possible. The tool vectorizes
    where possible and minimises IO calls. Adding more granular progress reporting would require breaking vectorisations
    or making smaller (and more) IO calls.

As an example:

.. code:: python

    from pytuflow import XMDF


    def progress_callback(done: int, total: int):
        percent = done / total * 100
        print(f'{percent:.0f}%', end='')
        if done >= total:
            print(' Done!')
        else:
            print('...', end='')

    
    res = XMDF('result.xmdf')
    df = res.flux('line.shp', callback=progress_callback)

Script output:

.. code:: bash

    0%...57%...86%...100% Done!

Bug Fixes
---------

- :ref:`pytuflow-arr` - Fixes the event name padding. There was a minimum padding of 2 digits, e.g. 1% AEP event would be output as ``01p``
  when it wasn't required to be padded.

Other
-----

- Better logging has been added when duplicate IDs are encountered for a given result type and domain in the
  :class:`~pytuflow.TPC` class. E.g. when there is a PO line "H" and PO point "H" with the same ID. Previously,
  this would cause a Python error when loading, now it produces a warning and finishes loading. Although, extracting
  results from a location with duplicate IDs is problematic since there is no differentiation between results, the wrong
  result may be returned.
